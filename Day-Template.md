# Mission Day Authoring Template (the generalized pattern + the *why*)

**Working document.** This is the reusable recipe for building **any** Mission Day, extracted from Day 1. `Day-1.md` is the fully worked instance; this doc is the **abstraction with the reasoning behind every decision**, so Days 2–4 (and later chapters, and automated generation) are **composition + review, not design-from-scratch.**

The point: once Day 1 is perfect, we don't re-perfect Day 2. We know *why* each Day-1 choice exists, so we can **replicate the intent** with new content. Read this before authoring any day.

- **Systems (how the machine works):** `Project-Archive-v3.md` (GDD).
- **Backend/runtime (how the machine is implemented):** `Backend-AI-System.md` (stack, schemas, deterministic Director, state, persistence, APIs, validation, build order).
- **Build (how we render it):** `Production.md` (verb catalog §2B, encounter model §2AA, district §6).
- **Implementation micro-spec (how each interaction is coded):** `Interaction-Spec.md` (markers, glyphs, tracked-read gate, encounter triggers/radii, gamified inputs, pacing, time model, feedback, tags — parameterized).
- **Worked example (a full day):** `Day-1.md` (beats B0–B13).
- **This doc:** the archetypes + laws + recipe that connect them.

## 0. The core thesis (every decision serves this)

**A Mission Day fuses three things that most edu-games keep separate: a game (you *do* things with skill and stakes), a living world (your actions cause real, remembered consequences), and learning (you leave understanding STAAR-required history).** These are not layered on top of each other — they are the *same* beats. The design bar is that no beat is only one of the three.

**The core architecture — two decoupled loops.** This works because learning and agency are separate systems that meet but never override each other:
- **Learning is a *closed* loop (guaranteed).** Required carriers + the three-stage gate + reroute (L3, L2) mean every player leaves with the same STAAR mastery no matter what they do. It is verifiable and deterministic and cannot be broken by any choice, failure, or path.
- **Everything else is an *open* loop (reactive).** Skill, timing, tagged choices, relationships, routes, informers, the time economy (L4–L18) drive real consequences and world-state that genuinely change *how the game plays*.
The open loop feeds *into* the closed loop's delivery — the Director reroutes the curriculum through whatever state the player creates — but can never *break* it. So **agency is real because consequences bite, and learning is safe because it reroutes.** Most edu-games collapse these into one and lose either the fun or the guarantee; keeping them decoupled is what lets us have both. Every law below serves one loop or the bridge between them.

**The three-legged acceptance test (apply to EVERY beat).** Before a beat ships, it must answer yes to all three, or it's cut/reworked:
1. **Game** — does the player *do* something (a skill, a choice, a traversal), not just watch/listen?
2. **Living world** — does it cause a consequence the world remembers (a stat, an object, a route, a later reaction)?
3. **Learning** — does it advance a STAAR-required concept (exposure, understanding, or demonstration)?

*Why:* the whole project failed its first playtest because beats were passive ("all you're doing is listening, there's nothing to DO"). The fix wasn't more content — it was making every beat pull its weight on all three legs at once. This test is the guard against regressing to a wrapped slideshow.

**Corollary — no committed time is wasted on non-learning; embed learning *into* actions.** If a choice costs real time (a hands-on action like helping), it must **carry its learning inline** — the character delivers the teaching *while* you work — so time spent also taught something. This is **not** a "work and talk" option: keep options **distinct** (talk / work / leave, L8); choosing **work** simply *includes* its dialogue for free because you already paid the time. So **talk** = cheaper-time, learning-only; **work** = more-time, learning **plus** the action's payoff (trust / route / object); **leave** = cheapest, skips the learning here (it reroutes, L3). Work is the richer beat when the clock allows, and the player never has to choose between *doing* and *learning*. *Why:* the day is short and time is precious (L18) — any beat the player pays for should pull learning weight; wasting committed time on pure non-learning action is the one inefficiency we can't afford.

## 1. Design laws (the *why* behind the rules — these are global, not Day-1-specific)

Each law is stated with its rationale so it can be applied to new content correctly. Cross-refs point to where the rule is enforced in detail.

### L1 — Only STAAR concepts gate a day, tied to that day's event, fairly portioned
Daily required-understand concepts are **only** the STAAR-assessed 8.4(A)/8.4(B) items, each assigned to the day whose fixed event naturally carries it, and portioned so no day is overloaded (Boston = 3/2/2/1). *Why:* "we don't need random shit for the daily stuff, only STAAR concepts." Non-assessed history (organized resistance, non-importation, Sons of Liberty, occupation, propaganda, Tea Act mechanics) is **scene context that stages the assessed concepts, never a gate.** Context is free to be rich; it just never blocks day-end or gets quizzed. Enforced: GDD §36 Per-Day Ledger; instantiated in `Day-1.md` §2C.

### L2 — Every gated concept clears three stages; reassessment is spaced across days
Per concept, on its learning day: **Learning** (≥3 **tracked** occasions across ≥2 interaction types) → **Understanding** (one Archive Sync) → **Demonstrating** (an applied *game action*, not a second Sync). **Only tracked exposures count** — a focus-read the player opened, a conversation they entered, an object they handled, a directed scene they were routed into. **Ambient content (background barks, decorative wall posters the kid may ignore) is passive support and never counts** — it can't be verified, so if reading is meant to count it must be authored as a trackable interaction, not left on a wall. **The Archive handler may still gently prompt ambient teachable content** (a light *"worth a look"*) to invite a curious player in — pure courtesy; it *still* never counts and skipping costs nothing. This lets the world be richly teachable without any of that richness becoming load-bearing: the guarantee lives entirely on the tracked set, ambient is a free optional layer the handler can spotlight. **A beat *before* the concept is revealed does not count either** — you can't be exposed to something you haven't been shown (e.g. operating the press before the stamp is pointed out is a *skill* beat, not a Stamp exposure). **Audit honestly:** before authoring a concept's understanding Sync, confirm ≥3 genuinely-tracked, post-reveal occasions actually *fire* on the real path — don't assume the ledger's rows all land. (Day-1 playtest caught the Stamp Act reaching its check with only 2 clean exposures; a tracked courthouse-board notice was added as the honest 3rd.) **Miss handling is bounded.** A miss on the **first** understanding Sync is silent + positive-only; the Director re-offers **one authentic exposure and one later retry**. If that retry also misses, it holds in place, gives a directional nudge (not the answer), and requires correction before leaving — no second reroute cycle. **Once a concept is Understood, its checks correct on the spot — never deferred, never re-pooled (loop-prevention).** Any miss in the same-day demonstration or a later-day reassessment gets immediate feedback + a forced on-the-spot correction: the beat holds in place (usually 1st-person, interaction still open), the handler/NPC gives a directional nudge (never "wrong", and not the answer), and the player must fix it to leave the beat, at which point it flips to Demonstrated / re-passes. It is not returned to the reintroduction pool. Reroute (L3) applies only to a demonstration/reassessment that never fires (understanding not ready / beat skipped), not to an in-scene miss. **Ground exposures in real artifacts, not summaries.** When an exposure is a document/source, prefer showing the **actual period artifact** (a real newspaper column, a Crown notice, a broadside) the player can read, over an abstract "context card." Even authored **intake context should flash the real source** in the Archive hologram before transport (Day-1 B0), so the very first exposure is a concrete thing seen, not a bullet, and it previews the tracked reads to come. There is **no persistent regression loop after Understanding**: a later miss creates only a transient correction-required state inside that same interaction. A day cannot end until all its gated concepts clear all three stages and no required correction remains open. **Reassessment lives on later days** (a prior-day concept re-tested in world or via Sync; ≤3 questions per Sync, Day 2+), which is where true spaced repetition happens. *Why:* understanding must be earned and durable, not exposed-once; spacing across days aids retention and keeps any single day from becoming a quiz block. Enforced: GDD "Concept Learning Lifecycle."

### L3 — Required learning never depends on skill, choice, or luck (carriers reroute — and reroute is TYPE-AWARE)
Each day declares **required carriers** (the content that must land on *every* path). Missing a delivery, failing a skill check, getting caught, or avoiding an encounter must **reroute** the carrier through another beat — never lose it. Skill and choice change *relationships, objects, route, and flavor*; they never change *whether you learn*. **Reroute is type-aware, not just count-aware.** Because L2 needs **≥3 occasions across ≥2 types**, the Director tracks per concept both `occasions` *and* the **set of types seen**, and reroutes to fill the **missing type**, not merely the count. Design for the **fully-avoidant path** — a kid who *coincidentally* keeps picking the non-expository option (only reads, or only talks, or skips reads) must still finish with 3 occasions / 2+ types. Maintain a **guaranteed fallback pool per concept, spanning types, anchored on beats the player cannot skip** (the day's unavoidable delivery/handling, the fixed event as a directed scene, the day-close convo, Director-placeable posted reads). **Best-effort spread for engaged players, guaranteed delivery for avoidant ones** — the spread degrades gracefully (a denser back-half), the guarantee never bends. (Day-1 §7A worked example.) **But reroute protects the *curriculum*, not the player from *consequences*.** A missed/failed/avoided beat still carries its full **legible relationship and world fallout** — an employer's trust/respect drops with a named cause (a missed delivery: "the rider left without the bundle"), a route stays shut, an informer acts — and it can carry into later days (L5 cascades, L18 time). Learning always lands **and** stakes are always real; the two are independent. Never make a miss consequence-free just because the lesson is safe — that would drain the stakes that make choices matter. *Why:* agency and difficulty are motivating only if the curriculum is guaranteed regardless, *and* only if failure still costs something a player cares about. Enforced: GDD RequiredCarrierContracts; `Day-1.md` §2 + §7 reroute matrix.

### L4 — Player-authored, not game-imposed (convert scripted beats into player actions)
Wherever the game would *script* a moment (a fumble, a stumble, a lucky catch), convert it into something the player does — **same seconds, same content, passive→active at zero time cost.** Critically, **failure must be self-attributable**: a smudged proof because *you* mistimed the pull is fair and motivating; a smudge the game forces to move the plot is a cheat that deters. *Why:* "whether the game forces you to mess up or you mess up yourself, nothing changes except UX" — and self-caused outcomes are the ones players accept and learn from. For delayed effects, add a **callback** so cause↔effect stays legible. Enforced: `Day-1.md` §5.

### L5 — Stats never move arbitrarily; causality is always legible
A relationship stat moves for exactly two reasons, both visible to the player: **(a) a tagged choice** (effect tag shown *before* clicking, card confirms *after*) or **(b) graded activity performance** (stake telegraphed before, card confirms after with the reason). No ambient drift, no "she just likes you now." *Why:* "it can NEVER be arbitrary — we can't change stats without the user understanding why." One action may **cascade** to several stats/characters over time (commit at the cause, reveal when it's felt in-fiction). **Stat effects are contextual, not flat deltas — calibrate to the current state.** The *same* action lands differently depending on where the stat already is. From a **lowered** state, a cheap honest act (an apology) *recovers* toward baseline for free, while a costlier effort (spending time to actually fix it — a reprint) can *overshoot above* baseline. So a mistake plus a genuine fix can leave the player **better off than never erring** — dynamic, legible, and it rewards investing time to make things right. Author outcomes as **state-relative moves** (recover / overshoot / hold / drop), always confirmed by the post-commit card with the cause. **Cascades and character unlocks are contingent, not guaranteed:** a committed delta realizes *only if the player reaches the moment it's felt.* If the reveal-interaction never happens (a character is never met — a delivery missed after being swept into the fixed event, L19), the character stays **locked at baseline**, the delta **never lands, and is lost — not deferred** (meeting them a later day is a fresh baseline interaction). This is the dynamic world-state at work; learning is unaffected (the carrier banked elsewhere), so a missed reveal costs **stakes, never curriculum** — the two-loop split (§0). Enforced: `Day-1.md` §4A; GDD §11.

### L6 — Relationships are dimensional, but most characters carry one dimension
Model the dimension that actually has *consequences* for dealing with a character, and pick the one that genuinely *fits* that person rather than defaulting to "trust" for everyone: e.g. **Thomas → Obligation** (help him, he owes you a favor → the dock route), **Pike → Respect** (competence at the craft — a sloppy proof reads as sloppy work, not dishonesty), **a Loyalist → Political read**, **a courier → Trust** (plain reliability/discretion). The **chapter anchor** (Abigail) carries a few (Trust for reliability / Respect for competence / Warmth for personal regard), and *which* one moves is beat-specific. Baselines are **low-neutral (~30–40%, shown as a band, never a number)** — everyone starts guarded, not blank or hostile. *Why:* "humans feel more than trust/mistrust," but giving every minor NPC five bars is noise and cost; one meaningful dimension per character + one rich anchor per chapter is cheap and deep. Enforced: `Day-1.md` §4A; GDD §11.

### L7 — Consequences reshape the world, using period-correct authority
Standing opens or closes the *actual world*: trust unlocks a route (state-gated blocker, not new geometry); a bad read makes an NPC inform on you and forces an evasion beat. Enforcers must be **historically correct for the date** (1765 = customs officers, constable, Loyalist informers; **no British troops until 1768**; redcoats/sentries appear in the 1770 day — itself a teaching beat). *Why:* a living world means choices change the map and the danger, not just the tone — and the *mechanism* of danger teaches the period. Enforced: `Day-1.md` §4A; GDD §9A.

### L8 — Choice legibility: tag consequential choices, leave probes untagged
Consequential options carry 1–3 tiny effect tags naming the *stat + direction* (`costs time` · `builds trust` · `reads as a threat`). Free probes and pure skill/look actions carry **no tag**. *Why:* the tag's *presence* signals a **stat/relationship/risk** consequence — an untagged option reads as "no strings *to a stat*," so players tell a consequential decision from idle curiosity at a glance. (Time is the exception: *everything* you do costs a little time (L18), but that ambient cost is felt via the clock, not tagged per probe; only notable time chunks get a `costs time` tag.) Options are **2 minimum, 3 maximum, distinct, specific, and each plausible** (never pad to three, never a filler option like "take a breath" for a player who isn't tired). **Plausibility includes *role-fit*:** the player occupies a specific low-status cover (a print-shop runner, a telegraph boy) — options must be things *that character* could plausibly do or say. A runner can't advise a clerk on the law or explain a tax to an expert; **expertise and learning flow from NPCs to the player, never the reverse.** Ground choices in the job (own a bad delivery, offer a reprint, pick a route, ask a question), and let NPCs carry the teaching. **The 3-cap is absolute: a free probe is never a bonus 4th option** — it either *is* one of the ≤3, is folded into a choice, or is cut (if the NPC already volunteers the learning, no probe is needed). Never present "three options plus a probe." **Frame every ask diegetically:** the NPC or handler states *in-character what the player is being asked to do* right before a decision (especially a multi-step construct), so the player never stares at options wondering what the question is; frame the job, never hand the answer. **In a knowledge check, options must discriminate on the *concept*, not a surface trait** shared by all of them (bad: "which is what's taxed?" when every option is paper; good: "which is the sort of *document* the stamp goes on?" splitting legal doc vs. private writing vs. a good). Prefer distractors built from **people/objects the player has actually met** so each reads as concrete. Enforced: `Day-1.md` §5.

### L9 — Two activity tiers: graded vs. effort (only fail where failing teaches)
An activity is either **graded** (input quality changes outcome + moves stats/object condition, e.g. the press pull) or **effort/unfailable** (a mash/hold that always completes; embodiment without a test, e.g. hauling cloth). Same animation/prop machinery; only outcome logic differs. **Timed graded activities default to oscillate + accelerate** (a needle/window that sweeps back and forth and speeds up each pass), so "wait for the perfect frame" is never the dominant strategy and hesitation costs. *Why:* skill expression is great where the outcome *means* something, but forcing failure where it teaches nothing is pointless frustration, and a static timing target is trivially gamed by waiting. Enforced: Production §2 / `Day-1.md` §5 / B2 press pull.

### L10 — Read the room: self-driven vs. guided vs. prompted
- **Self-driven** (no prompt, no marker): the next action is obvious with no distractors (leave a one-door empty room). Never wrap it in a "1. Leave" button.
- **Guided** (marker, no choices): only one thing to do but it's unclear *where* (drop off a roof → "get to Abigail's"). Gold marker on the destination + Archive nudge if they wander.
- **Prompted** (options): the scene is open/busy/distracting *and* there's a real decision. Present 2–3 tagged options.
*Why:* over-prompting an obvious action wastes attention; under-guiding in an open scene wastes time and loses the player. Match the UI to the situation. Enforced: `Day-1.md` §5.

### L11 — Idle is the Archive's job; the living world only ever teaches
If a player stalls, the **Archive AI** gives a gentle, escalating task reminder. NPC approaches and world-state shifts are **precious authored teaching content**, never used as anti-idle guards. Routine traversal is **cheap** (the rider is ~20s away; walking costs nothing) — time blocks are spent on *choices*, not footsteps. *Why:* conflating "keep the player moving" with "teach the player" burns authored content on nagging and makes the world feel like a chore-nag. Separate the two cleanly. **Gold-marker redirect (rule of thumb):** whenever a **gold** (selected/urgent) marker is live and the player heads away or idles, the Archive **warmly redirects them back to it** (gold stays lit; line escalates only if ignored, merging with the time-warning near dusk). One rule covering every gold objective (the crowd-steer, the shop-exit nudge); **blue** unselected pings never redirect. Enforced: `Day-1.md` §4/§5; Interaction-Spec §1.2a.

### L12 — The HUD is diegetic; the Archive is one surface; feedback is positive-only
Everything on screen is the player's **AR overlay** (Archive tech, invisible to 1765); the **Archive AI is a JARVIS-style handler** (calm, terse, drives assessment diegetically). **Two separate voices (hard):** in-world NPCs know *nothing* of the Archive/AR/HUD/"filing"/Syncs/Notes/stats or the time-travel frame (it's the player's private layer), so an NPC line, including any in-beat correction, is grounded **only in what that person could know in-period**; the **handler is the sole voice for meta/assessment**. Never let an NPC reference the overlay. **Writing voice (hard, all in-fiction text — dialogue, handler lines, field tags, flicker/card labels, signage):** human, short, concrete; **never use em dashes (—)** (use a period, comma, or colon) and no chatbot-cadence tells ("it's not just X, it's Y", over-hedging, stacked clauses). Design prose in the docs may use dashes freely; player-facing text may not. The always-on **Today strip is the Archive's collapsed state** — expand it into Today/People/Notes/Routes. **First contact with any character fires an "person added" unlock flicker** (same feedback family as route-unlock flickers and stat cards); its People-panel silhouette resolves to a real card, and any delta already committed against them reveals then. **Notes shows only *understood* concepts** — the entry + "Added to Notes" flicker fires **once, at the concept's first Understanding Sync** (positive-only; a first-understanding miss gets **no** "wrong" callout, silently re-offered later). The later demonstration and any reassessment are **not** re-announced in Notes (already there → diegetic confirmation only). Markers: **blue ping = available option (with live distance), gold = selected/urgent**; **markers and the Today strip are one coupled system** (strip = what's left, marker = where, always in agreement) and follow **pick-one-focus**: at a selection point all pending objectives show (N blue pings + N strip lines); selecting one collapses to a single **gold** ping + strip line while the rest hide. For a **must-do-all, order-free** set (e.g. the day's deliveries) the hidden ones **resurface after each completion** (3→1→2→1→1); for a **mutually-exclusive** choice (e.g. a route) the unchosen options **vanish for good**. The strip also **evolves with the task set** (it starts as the single current objective, then becomes the day's list). **Speech glyph + attributed subtitle on all ambient NPC speech; a separate interaction glyph marks engageable NPCs.** **Ambient background chatter runs the whole day** — passersby and shopkeepers trade short overheard lines carrying real period exposition (each with the speech glyph + subtitle), as **soft support that is never tracked** (never counts toward the L2 gate, ignoring it costs nothing); it makes the street live and rewards a curious ear beneath the authored/tracked curriculum, and ducks under any active dialogue/Sync/Archive line. *Why:* one coherent in-world interface (not a game-y overlay), and never telling a 13-year-old they're "wrong" (which deters) while still gating on real understanding. Enforced: GDD §16; `Day-1.md` §4A/§5; Interaction-Spec §2.1/§1.2a; Production §2AA.

### L13 — Curriculum cinematics: author once, all routes funnel in, every route keeps gameplay
A set-piece that carries required curriculum is authored **one time**; every legal route **funnels into the same cinematic**, so it can't be missed. What the route changes is the **interactive on-ramp** (climb to a vantage / push-through + unfailable dodge / hold-to-chant), each ending in a handoff (gold "observe" zone / camera pan / trigger). **Cutscene budget, three tiers:** pre-rendered only for **STAAR-named landmark events** (Tea Party, Massacre tier); **in-engine directed** for every other curriculum moment; **staging + barks** for ambient. *Why:* airtight curriculum delivery at one-time cost, and cutscene production is expensive so it's rationed to named events only. Enforced: `Day-1.md` §5; Production §7 + §2AA active-witness pattern.

### L14 — Pattern-complete: reuse the verb catalog, build no new interactions per day
Every player action is one of the ~17 canonical verbs (Production §2B). Day 1 exercises all of them once, so the reusable toolkit is proven; **every later day is those verbs rearranged with new data — no new interaction/animation engineering.** *Why:* this is the entire basis for finishing 4 days (and future chapters) in the timeline — authoring becomes composition. When designing a new beat, **pick an existing verb**; if you're tempted to invent one, stop and recompose. Enforced: Production §2B; `Day-1.md` §10 pattern check.

### L15 — Writing: short, oblique, human, kid-natural (no lecture, no AI voice)
NPC lines are one or two short lines that *imply* the point; the character never spells out or names the concept (that's the field tag's job). **No em dashes, no "not X but Y" balance, no essayistic exposition.** Free-probe labels read the way a 13-year-old thinks ("ask him about the prints," not "ask who's financing the printing"). *Why:* kids infer meaning from how people offhandedly talk; exposition-dumping and on-the-nose labels break immersion and condescend. Enforced: `Day-1.md` §5.

### L16 — Space is a gameplay construct; one district, re-dressed; spend budget on the iconic image
Build **one shared district once** and author per-day **state-layers** (lighting, dressing, crowd, open/blocked routes). Compress distance freely (never teach a false geographic *fact*). Each day gets **one unmistakable iconic shot** (the memory hook); the rest works quietly. *Why:* re-dressing one district is the single biggest reason all four days fit the timeline, and it's historically legit for a small peninsula. Enforced: Production §6.

### L17 — Gamify the *execution* of any action-bearing choice (camera by fit; only pure dialogue is exempt)
Once a decision is made, never auto-resolve or cut away from the *doing* **if it involves real movement or animation** — give the player a short gamified **execution**, in whichever camera suits the action:
- **First person** for precise **hand/fine-motor** work (tuck, fold, wrap, clean, pour, cinch, handle, operate, read) — you see only hands + object, which sidesteps 3rd-person fine-motor animation *and* makes close-up content readable/**tracked** (L2).
- **Third person** for **gross-motor/spatial** action (dodge the thrown rock, vault, climb, duck, push through a crowd, evade) — where seeing your body move in space is the whole point.

The **decision already happened** (this adds no new choice); the execution is a small **effort-tier** mechanic (drag / fold / hold / swipe / time-a-press). It pays off three ways: **more fun**, **sidesteps hard animation** (via the fitting camera), and (in 1st) **makes content legible**. **Pure dialogue or cognitive choices are exempt** — there's nothing to execute. Apply to **learning and non-learning moments alike**; the more action we make hands-on, the more physical the world feels. Zero decision-time cost, pure UX/engagement gain. *Why:* the general form of the press-pull insight — execution should be something you *do* in the right camera, not something the camera hides. Cross-ref: L4 (player-authored), L9 (effort tier), Production §2A/§2B (camera-by-fit).

### L18 — Time is a spent resource that shifts the day-state and reshapes later interactions
No numeric timer — the day runs on a felt **"sun + crowd" clock** with a fixed **dusk cutoff** (the fixed event). Choices trade along a **time vs. risk** axis: a **safe** option usually `costs time`, a **fast** option is `risky`. Time is **cumulative** — every time-costing choice (plus detours, helping, failed-risky retries) advances the day toward dusk, and that accumulated total **moves the world along an escalation curve**: watcher heat, crowd density, character agitation, which encounters fire, and which options remain all rise/shift with the hour. So **later interactions adapt to how much time the player has spent** — the *same* later beat is calmer after a brisk run and tenser after a slow one — and dawdling past dusk resolves unfinished objectives as missed → reroute (learning still lands, L3). **The dusk fixed event is a hard *interrupt*, not a passive timeout** — if the player is still mid-errand when the crowd hits critical mass, the event *pulls them in* and any unfinished delivery closes as missed on the spot. This is what gives time its teeth and makes tradeoffs bite: e.g. **helping a character (Trust + a route unlock) burns time; if that tips past dusk with a delivery still undone, the event sweeps the player up before they reach it, the delivery misses, and the employer's standing drops** (L3 stakes) and carries forward. The good choice now can cost the good outcome later — opportunity cost is the point. The world/Director reads the current time-state and adjusts downstream beats to it. **Nothing you *do* is truly free — time is a gradient over interactions.** Because the clock is coarse (discrete beats, not a 24h timer), every interaction advances the day a non-negligible amount: **deliver-and-leave (least) < short dialogue/probe (small) < hands-on action like helping (most).** A "free probe" is free of *stat/risk* consequences, **not** of time. **Only movement/traversal is cheap** (footsteps don't burn the day), and idle *wandering* is handled by the Archive nudge (L11), not charged. To avoid tag-spam, routine small time costs are **ambient/felt** (sun, crowd), not tagged; a `costs time` tag marks only **notable** chunks (helping, detours). **A persistent day-clock lives on the HUD, diegetic and non-numeric** (a sun-arc / daylight meter on the Archive strip, *not* a countdown) so the player is never blind to how close dusk is; it **advances during an interaction proportional to that beat's authored `timeCost`** (the sun visibly creeps as you work, long actions eat more daylight than a quick probe), off the *same* per-verb cost table that drives escalation, and traversal never moves it. As daylight runs short the **Archive gives polite, escalating time-warnings** (distinct from the idle-nudge: idle fires on wandering, these on genuine time-scarcity), ending in a **must-acknowledge "shops are closing" interrupt** if the clock runs out with errands undone (confirm → unfinished errands close as missed + reroute + relationship stakes). **The crowd/fixed event forms by the *hour*, not by "errands done"** — however the day went, the player funnels into it. *Why:* in an actual world nothing is free — making even small interactions nudge the day (while keeping movement cheap) makes "safe but slow" a genuine, accumulating trade and the world honestly responsive to the player's pace; the diegetic clock + warnings keep that trade *legible* without a game-y timer. Enforced: `Day-1.md` §4/B10.4; Interaction-Spec §8.

### L19 — Every day is anchored by hard, time-locked fixed event(s) that always fire
Each Mission Day has **at least one immovable historical event** (the Aug 14 crowd action; the Boston Massacre; the Tea Party) that is **scheduled on the clock and fires no matter what the player does** — it cannot be prevented, delayed, or skipped, and its required carrier commits when it fires. These anchors are the day's fixed points and its **hard dusk-interrupt** (L18): when the clock reaches them, they take over. What the variable day changes is only the **world-state the player meets the event in** — which errands are done vs. missed, relationship bands, watcher heat, time of arrival, and which gameplay **on-ramp** they take into it (climb / push-through / chant, A11). So the event is invariant; the *experience and consequences around it* are the player's. *Why:* this is the closed-loop fixed spine (§0) expressed on the clock — **history happens on schedule; you choose how you're standing when it does.** Treatment follows the cutscene budget (L13): only STAAR-named landmark events (Tea Party, Massacre) get pre-render; others are in-engine directed. Enforced: `Day-1.md` B11; GDD Historical Events.

### L20 — Each day has a hard, path-invariant learning payload; size the day to fit it spread out
Before authoring beats, compute the day's payload from its gated-concept count **T**. Per concept, on its learning day (L2): **3 tracked exposures + 1 understanding Sync + 1 day-of demonstration** (an applied *game interaction*, never a Sync). So a day owes a fixed, countable payload:

> **4T tracked learning moments** = 3T exposures + T demonstrations · **plus T first-understanding questions.** *(Day 1: T=3 → 12 tracked + 3 one-question Syncs. Day 2+ may group up to three questions in one Sync.)*

- **Guaranteed regardless of path.** Every one of those tracked moments + Syncs **must land no matter what the player picks or how world-state/relationships shift** (§0 closed loop; L3 reroutes anything missed). Choice changes *how* it's delivered, never *whether* or *how many*.
- **Spread, never batched.** Understanding Syncs fire only once a concept's exposures complete, and are **interleaved across the day** (roughly: one midday, one after the last errand, one near the fixed event/close). They may sit **relatively close but never back-to-back** — the Director enforces **at least 2 interactions between any two Syncs** (deferring one to the next natural opening if the last was too recent). The T demonstrations are likewise **distributed across the day's applied/construct moments** — do *not* cram all demonstrations into a single end-of-day construct.
- **Day-of demonstration = interaction; cross-day reassessment = either.** On the learning day the stage-3 demonstration is always a **world game action**; on **later** days a prior-day concept may be reassessed **in-world OR via Sync** (≤3 questions/Sync, which may fuse topics for synthesis). That later spaced-repetition is *additional* to each day's own payload.
- **Size the day to the payload.** If the errand/beat count is too small, the payload crams and the day feels like a quiz — **add touchpoints, stops, or mid-day applied moments** so `4T + T understanding questions` land naturally spread. **Audit the count fires on every path** before locking the day (Day-1 playtest caught economic-policy reaching its Sync with only 2 tracked and all 3 demonstrations batched at the finale — both fixed by stretching the day). *Why:* the closed loop is only "closed" if it's *quantified and guaranteed*; spreading it is what keeps the guaranteed content from collapsing into a test. Enforced: `Day-1.md` §2D; GDD "Concept Learning Lifecycle."

## 2. What a day needs as *input* before authoring

Gather these five before writing beats (all derivable from the GDD chapter spec):

1. **Fixed event + date** — the immovable history the player moves *through* (never alters). (Boston: Stamp Act 1765 / Massacre 1770 / Tea Party 1773 / Port Closure 1774.)
2. **The day's STAAR concept set** — from GDD §36 Per-Day Ledger (L1). This is the day-end gate.
3. **Prior-day concepts to reassess** — spaced repetition schedule (L2); which earlier concepts get re-tested today, in world or Sync.
4. **Anchor + world carryover** — the relationship bands and world flags inherited from the previous day (Abigail Trust/Respect/Warmth; Thomas dock-route favor; "Clarke marked you"; etc.).
5. **District re-dress** — the state-layer for this day (Production §6): lighting/season, set dressing, crowd, which routes are open/blocked, where the fixed event stages.

## 3. The beat archetypes (Day 1's B0–B13 generalized)

Day 1's beats are not one-off content — each is an **archetype** reused every day with new data. For each: **Pattern** (the reusable shape) · **Why** (the reasoning) · **Instantiate** (how to fill it for a new day). The **Day-1 instance** is cited as the worked example.

> Not every day uses every archetype, and order can flex — but the **spine** (intake → job → assignment → errands/encounters → synthesis Sync → fixed event → demonstration → close) is the reliable skeleton.

### A0 — Archive intake & temporal insertion  *(Day-1: B0)*
- **Pattern:** open *inside* the Archive as the player is transported: identity sync → ≤25s context record (the only opening exposition) → **diegetic assignment** ("Report to [anchor], [role]") → dissolve into the world with a gold marker on the first objective.
- **Why:** establishes framing and the day's one piece of necessary context without a lecture; the assignment is a *task*, not an academic "driving question" ("that's on the nose and dumb") — curiosity comes from the tense world, not from the Archive stating the lesson.
- **Instantiate:** swap date/cover/context card to the new event's setup; assignment points at the day's first beat; context card carries any prior-chapter recap. Commits the day's context carrier (e.g. debt→policy exposure #1).

### A1 — Arrival into the workplace  *(Day-1: B1)*
- **Pattern:** a short, self-driven or lightly-chosen entry into the anchor's workplace (knock / walk in / glance).
- **Why:** belonging is established through *work*, not cutscene; the player should physically arrive, not "spawn in." Onboarding-by-doing starts here.
- **Instantiate:** same shop, re-dressed for the day; entry line reflects carryover (a warmer greeting if Abigail trusts you).

### A2 — The Job (occupational skill beat, usually graded)  *(Day-1: B2 press pull)*
- **Pattern:** a **graded** skill mechanic built on an existing verb (Operate/Construct), input quality → clean/usable/smudged, which **moves stats + object condition and cascades forward.**
- **Why:** the day is "a real day at work"; skill expression gives the player something to *do* with real stakes, and a graded outcome seeds cascading consequences (a clean proof lifts Abigail's respect *and* shapes Pike's first impression hours later). **Learning is never gated by skill** (L3) — the accessibility path yields "usable" + the same learning.
- **Instantiate:** pick the day's print-shop task; choose one graded verb; define the clean/usable/smudged downstream effects on that day's characters. Effort-tier (L9) if failure wouldn't teach.

### A3 — Handle the evidence (Focus-Inspect, surface the delta)  *(Day-1: B3 compare proofs)*
- **Pattern:** first-person Focus-Inspect of the physical object that *is* the concept; the meaningful difference is **authored-surfaced** (side-by-side, aligned, highlighted) — never a spot-the-difference hunt.
- **Why:** the concept should land by *handling the thing*, not being told; and "the difference shouldn't take two minutes to spot" — inspection is about meaning, not detection. Banks a required carrier in a safe location (so a later failed delivery can't lose it).
- **Instantiate:** choose the day's hero document/object; author the salient contrast; fire the field tag naming the concept; commit the carrier here.

### A4 — Assignment + route choice  *(Day-1: B4)*
- **Pattern:** the anchor loads the day's objectives (deliveries/tasks); the player **chooses route/order** (the first time/exposure decision). A gold marker (single) or blue pings (multiple) guide.
- **Why:** agency + the exposure/time economy start here; route choice is where encounters, watcher-heat, and trust-shortcuts live. Early exposures can be planted here (e.g. a street broadside).
- **Instantiate:** define the day's objective nodes; assign per-route tags; plant early concept exposures on the walk.

### A5 — Delivery + consequential social + free probe  *(Day-1: B5 Thomas, B6 Pike)*
- **Pattern:** reach a character; **hand off** the object; a **consequential social choice** (tagged, moves their dimension) plus **free probes** (untagged, information only). Their card unlocks on first meeting (cascade reveals here).
- **Why:** this is where the living world and learning fuse — the delivery is the game action, the social choice is the consequence, the character's lines are the exposure. Distinguish consequential (tagged, costs/moves) from probes (free) so "1 and 3 don't both mysteriously build trust."
- **Instantiate:** each character teaches one concept via short oblique lines (L15); one tagged social choice on their single dimension (L6); 1–2 free probes; unlock their People card + reveal any cascaded delta with its cause.

### A6 — Perspective / mistrust encounter (opt-in, proximity-gated)  *(Day-1: B7 Clarke)*
- **Pattern:** an NPC **staged on the route** (never chases you); AR glyphs signal presence; entering their zone (with a trigger, e.g. exposed item) opens a choice whose outcome can turn the world against you (informer → evasion beat). Avoidable via distance/alt route.
- **Why:** kills the "everyone agreed" misconception by voicing a real opposing view, and makes standing *matter* to the map. Intent is carried by **spoken line + staging, never subtle gaze animation** (we can't animate a meaningful glance without mocap) — "he just asks 'what's that in your bag?'"
- **Instantiate:** pick the day's dissenting/authority character; one political-read choice; wire the mistrust outcome to a period-correct enforcement beat (L7).

### A7 — Traversal / evasion under pressure  *(Day-1: B8)*
- **Pattern:** third-person route choice through a tensing world (fast-exposed / slow-safe / trust-unlocked shortcut), with canned Traverse clips (vault/duck) where a lane closes; visibility/heat state.
- **Why:** movement is active and spatial (the tension is *in* the world), and route choice pays off the relationships built earlier (the dock route you earned). Traversal is cheap (L11).
- **Instantiate:** re-dress the street spine; set which shortcut is unlocked by which relationship; define what feeds the conditional caught branch.

### A8 — Conditional "caught" branch (fair, unlucky, still teaching)  *(Day-1: B9)*
- **Pattern:** triggered by a failed risky route / being informed on / high heat; an authority stops you; choices to comply / talk out / slip away; teaches a concept (e.g. writs of assistance) and can cost an object — **but never dead-ends** (learning reroutes).
- **Why:** getting caught is a *teaching branch*, not a fail state (L3, L4); the search itself carries curriculum, and the outcome is self-attributable (you took the risky lane).
- **Instantiate:** period-correct authority (L7); the concept the stop teaches; the object at risk + its reroute.

### A9 — Timed handoff  *(Day-1: B10 rider)*
- **Pattern:** a delivery on the day's one clock (the departing rider), signaled by the waning-sun/bell glyph on the Today strip; a small tense choice (quick/exposed vs. wait-for-a-gap).
- **Why:** the day's single felt deadline (no numeric timer) — time is conveyed diegetically (lengthening shadows, the bell, the strip glyph), not a countdown UI.
- **Instantiate:** define the day's one timed objective; everything else is deadline-free so the clock stays legible.

### A10 — Archive day-synthesis Sync (the close driver)  *(Day-1: B10.5)*
- **Pattern:** when the day's authored objectives are exhausted, the **Archive handler proactively steps in** with a short assessment ("before we file"), runs the understanding Sync(s) for the day's concepts (positive-only feedback), and **tees up the transition** to the fixed event.
- **Why:** "after the tasks are over, nothing else is defined — the Archive should come assess and drive what's next" (L11). Never leave the player idle in an open world; assessment → transition, never a dead stop. Understanding checks here; demonstration comes later (L2).
- **Instantiate:** one interleaved understanding question per not-yet-understood concept (spaced, not batched); each drawn from what the player actually handled; a handler line that sequences the wind-down.

### A11 — Fixed-event active witness  *(Day-1: B11)*
- **Pattern:** the day's fixed event, witnessed via the **active-witness pattern**: state-gated Traverse to a vantage / push-through + unfailable dodge / hold-to-chant — **all three on-ramps funnel into one authored in-engine directed cinematic** that guarantees the teaching shot (organizers elevated, lit, crowd obeys). Commits the event carrier.
- **Why:** witnessing must be *active* and the teaching must be *guaranteed-legible* (never "did the player happen to look?") — direction + salience + choreography carry it. One cinematic, many on-ramps = airtight + cheap (L13).
- **Instantiate:** author the event's one directed shot; provide 2–3 gameplay on-ramps that hand off to it; pre-render **only** if it's a STAAR-named landmark event, else in-engine directed.

### A12 — Diegetic construction / demonstration  *(Day-1: B12 set the headline)*
- **Pattern:** a **Construct** beat where the player *applies* the day's concepts to make something real (set tomorrow's headline + pick the evidence line). This is the **stage-3 demonstration** (applied game action, not a Sync) and can demonstrate **several concepts in one construct** (headline = representation, evidence = the tax + its cause). Misses create a transient correction-required state for that concept inside the same beat; they do not re-pool it.
- **Why:** understanding is proven by *use*, diegetically, not by a detached quiz; a single authored construct is an efficient, non-batched demonstration surface. A concept may only be offered as an option once it's at least Understood (choice-gating, L2) — unless this beat *is* its authored demonstration and prior stages are met.
- **Instantiate:** choose the day's construction task; map each gated concept to a sub-choice within it; author distractors that encode the day's misconceptions (spectacle-only, cost-only); define the correction flow.

### A13 — Day close  *(Day-1: B13)*
- **Pattern:** the anchor's end-of-day read (reflects how you ran the day); a **warmth-gated extra branch** (personal access + a Day-2 seed) if you banked enough; then the **Archive UI blooms full-screen for a warm, celebratory day-end card**; **invisible auto-save**; explicit **carryover** of bands + world flags into the next day.
- **Why:** the anchor relationship is the through-line across days; warmth should *pay off* ("if she really likes you, you get more options"); the full-screen Archive card is the one moment the overlay goes full-bleed, a positive "day filed" payoff (headline/artifact of record, the concepts earned into Notes today, who you met, what opened — never a grade or percentage); the save is backend-invisible; carryover is what makes the world persistent and the next day feel *changed*, not reset.
- **Instantiate:** author the anchor's read per band; the warmth branch's seed for the next day; the day-end card's congratulatory handler line + artifact + earned-concepts + relationship/route read; list exactly which bands/flags carry forward.

## 4. Cross-cutting systems every day instantiates (not re-authored)

These are built once and simply *populated* per day. Detail lives in the cited docs; this is the checklist of what to fill:

- **Relationships (L5, L6):** assign each new character exactly one dimension (anchor = several); set baselines low-neutral; wire every stat move to a tagged choice or graded outcome; plan cascades. → `Day-1.md` §4A.
- **Archive UI (L12):** populate Today (the day's objectives + timed glyphs), People (new cards), Notes (concepts that will be earned), Routes (any unlockable this day). The surface itself is built; you add data. → GDD §16.
- **Effect tags (L8):** attach to every consequential choice; leave probes clean. → `Day-1.md` §5.
- **Markers & glyphs (L10, L12):** gold/blue pings per objective; speech + interaction glyphs on NPCs. → Production §2AA.
- **Cinematics (L13):** classify each set-piece into the three tiers; author once with on-ramps.
- **Carriers + reroute matrix (L3):** declare the day's required carriers and, for each failure/avoid state, the beat that re-delivers it. → `Day-1.md` §7.
- **Historical grounding (L7, L16):** period-correct authorities/figures for the date; compression guardrails (no false taught fact). → `Day-1.md` §9.

## 5. The authoring recipe (automation-facing procedure)

To generate a new day, execute in order:

1. **Pull inputs** (§2): event/date, STAAR concept set (GDD §36), reassessment list, carryover, district re-dress.
2. **Build the concept ledger** (L1, L2): for each gated concept, plan ≥3 exposures across ≥2 types, one understanding Sync (spaced/interleaved), one applied demonstration. Add prior-day reassessment items (≤3 Q/Sync). Verify it fits ~15–30 min.
3. **Lay the beat spine** from the archetypes (§3): intake → arrival → job → evidence → assignment/routes → deliveries+encounters → timed handoff → synthesis Sync → fixed event → demonstration → close. Drop archetypes that don't fit the day; don't invent new ones.
4. **Assign a verb to every action** from the catalog (L14). If none fits, recompose — do not create a new interaction.
5. **Distribute the exposures** across the delivery/encounter beats so each concept hits its 3/2 threshold *before* its understanding Sync, and its Sync *before* its demonstration (spacing, L2).
6. **Wire consequences** (L5–L7): per-character dimension + one tagged choice each; cascades; world/route/informer outcomes with period-correct authority; carryover out.
7. **Author choices** to spec (L8, L10, L15): 2–3 distinct/specific/plausible options, tagged if consequential; pick self-driven/guided/prompted per situation; short oblique kid-natural lines.
8. **Classify set-pieces** into cutscene tiers (L13); author the fixed event as one cinematic with on-ramps.
9. **Declare carriers + reroute matrix** (L3): every required concept survives every failure/avoid path.
10. **Run the checks:** three-legged test on every beat (§0); pattern-completeness (no new verbs); day-end gate closes (all concepts 3-stage-clear); timing budget; historical guardrails. Flag anything unresolved as an explicit `TODO`.

**Human review** then confirms tone, historical accuracy, and fun — the expensive judgment — while structure/verbs/systems come pre-satisfied by the template.

## 6. What changes day-to-day vs. what's fixed

| Fixed (built once, reused) | Varies per day (the authored data) |
|---|---|
| The ~17 verbs + their camera/animation (Production §2B) | Which verbs each beat uses, with what content |
| The beat archetypes (§3) + the spine | Which archetypes appear, their order, their specifics |
| The Archive UI surface, markers, glyphs, stat cards | The objectives/people/notes/routes populated |
| Relationship system + causality rules (L5, L6) | Which characters, which dimensions, which outcomes |
| The shared district geometry (Production §6) | The state-layer re-dress + the day's iconic image |
| The learning lifecycle + gate (L1, L2) | The day's STAAR concept set + reassessment list |
| The active-witness + cinematic-tier patterns (L13) | The fixed event + its on-ramps |
| The design laws (§1) | Nothing — laws are invariant |

*Rule of thumb:* if authoring a new day tempts you to build a new **system, verb, or law**, stop — that's a Day-1 job that should already be done. New days only supply **data** into fixed structures.
